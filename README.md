# AP Tech Master - 応用情報テクノロジ完全攻略ラボ＆クエスト

応用情報技術者試験（AP）の最重要・最難関分野である**テクノロジ系**を、**「語源・背景ストーリー・動的シミュレーション・午後記述ロジック」**によって楽しく深くマスターするためのスマートフォン最適化Webアプリケーションです。

---

## 🎯 開発の背景とターゲット

- **対象者**:
  - 基本情報技術者試験（FE）合格済み
  - **非エンジニア**（プログラミングやインフラ構築の実務経験はないが、ITの本質を深く理解したい方）
  - 過去問演習で `ストラテジ系 ＞ マネジメント系 ＞ テクノロジ系` となり、テクノロジの克服が急務な方
- **解決する課題**:
  - 意味のわからない英字略称（RAID, CIDR, LRU, ACID 等）の暗記地獄から解放
  - 午前問題の丸暗記では太刀打ちできない「午後記述問題」への架け橋
  - スキマ時間（通勤・通学・就寝前）に片手スマホで「なるほど！」と腑に落ちる体験

---

## 🚀 主な機能と特徴

### 1. 🧪 6大体感ビジュアル・ラボ (Interactive Lab)
パラメータをいじりながらアニメーションで動作原理を目撃できる6つの専用シミュレータ：
1. **CPUパイプライン＆ハザード・フォワーディング**: 5段分業の仕組みと、RAWデータハザードをバイパス回路で解消する瞬間を視覚化。
2. **仮想記憶 LRU / FIFO ページ置換**: 「なぜ直近使っていないものから捨てるのか？」時間的局所性の原理を体感。
3. **サブネットマスク＆CIDRビット計算機**: 32ビットの境界線（/24〜/30）をスライダーで操作し、利用可能ホスト範囲を瞬時に計算。
4. **公開鍵・署名・ハイブリッド暗号**: 「誰の鍵で何をするのか？」SSL/TLSの黄金ルールをアリスとボブのキャラで直感理解。
5. **システム稼働率＆RAID 5復元**: 直列で下がり並列で跳ね上がる確率計算と、HDD故障時にXOR演算でデータが蘇る驚きを体験。
6. **DB正規化ステップパズル**: なぜ正規化するのか？「更新時異状」の悲劇を目撃し、第1〜第3正規形へテーブルを綺麗に分離。

### 2. ⚔️ 午後対策トラブルシュート・クエスト (Scenario Quests)
ストラテジ・マネジメントの文脈読解力を活かし、現場トラブルを解決する対話型シナリオ演習：
- **Quest 1**: ECサイトのタイムアウトとデッドロック事件（2相ロッキングとロック順序の統一）
- **Quest 2**: 新拠点オフィスのIP枯渇とVLAN/VLSM設計（ブロードキャストドメイン分割とプレフィックス計算）
- **Quest 3**: 偽装請求書メールとWeb不正アクセス撃退（SPF/DKIM/DMARCとプレースホルダ）

### 3. 📝 午前テクノロジ厳選ドリル (Morning Drill)
- FE合格者向けに特化し、「FEとAPの決定的な違い」「なぜ他の選択肢が誤りなのか」を全問完全解剖。
- 午後記述に直結する重要エッセンスメモ付き。
- 間違えた問題を自動ストックする「要復習フィルタ」搭載。

### 4. 🔤 語源・誕生ストーリー事典 ＆ 午後記述ロジック (Etymology & Logic)
- **語源事典**: 100語以上の重要テクノロジ略称を「英単語本来の意味」「先人が直面した課題と誕生ドラマ」「一言本質」で徹底解説。
- **午後記述フレーズ集**: 「なぜ共通鍵と公開鍵を組み合わせるのか？」などを30〜40字で言い切る定型ロジックと公式早見表。

### 5. 📱 スマートフォン最適化UI
- 親指が届く固定ボトムナビゲーションバー。
- PCで開いたときも「🖥️ 全画面 / 📱 スマホ枠（iPhoneモックアップ）」をワンタップ切替。
- 学習記録、クリア状態、EXPはブラウザの LocalStorage に自動保存。

## 🏃 起動方法

本アプリはビルド不要・環境構築不要の完全静的SPAです。

### 方法1: ブラウザで直接開く
`index.html` をダブルクリック（または右クリックして「ブラウザで開く」）するだけで即座に動作します。

### 方法2: ローカルHTTPサーバーで起動（推奨・スマホ実機アクセス可能）
Node.js がインストールされている場合：
```powershell
npx serve .
```
表示されるローカルIPアドレス（例: `http://192.168.x.x:3000`）に同一Wi-Fi内のスマートフォンのブラウザからアクセスすれば、スマホ実機でそのまま学習できます！

## 📚 非エンジニアのためのAPテクノロジ攻略の心得

1. **略称に出会ったらまずフルスペルを調べる**:
   アルファベット3〜4文字を丸暗記しようとすると脳が拒絶します。「英単語の直訳」を見るだけで8割の仕組みが分かります。
2. **「何が困ってこの技術が生まれたのか」を押さえる**:
   技術はすべて「先人が直面したトラブルの解決策」です。トラブルの文脈さえ掴めば、午後の長文問題はスラスラ読めるようになります。
3. **午後は「セキュリティ＋DB＋NW/システム構成」を狙う**:
   コードを書く問題（プログラミング）を無理に選ぶ必要はありません。論理的読解力とメカニズムの理解があれば、セキュリティ（必須）とデータベース、ネットワーク、システム構成で高得点を叩き出せます！

## 🛠️ コンテンツ正確性チェック＆修正履歴

技術的正確性の精査に基づき、以下の内容を修正・ブラッシュアップしました：

1. **RAIDの表記拡張 (`etymology-data.js`)**:
   - `fullName` を `Redundant Array of Independent Disks（旧称: Inexpensive Disks）` とし、現在の業界標準（Snia/IEEE/IPA）と1987年論文時の旧称を併記。
2. **MTBFの定義修正 (`etymology-data.js`)**:
   - 「故障と故障のあいだ」から「修復完了から次の故障までの正常稼働時間」へと定義を厳密化。
3. **CISC/RISCの開発経緯の精査 (`etymology-data.js`)**:
   - ジョン・ヘネシー（スタンフォード大 / MIPS）とデビッド・パターソン（バークレー校 / RISC-I）の所属・プロジェクト名を正確に分離・明記。
4. **午前ドリルの誤答解説の補正 (`drill-data.js`)**:
   - 実効アクセス時間計算問題（`q-proc-1`）の選択肢誤答値（27ns, 51ns, 75ns）とそのミス理由（ミス時合算ミス、確率逆適用など）を正確な計算パターンに修正。
5. **記述問題の文字数カウント補正 (`logic-data.js`)**:
   - 各模範解答の実際の文字数表記（lengthおよび問題文の指定字数目安）を正確な数値に更新。
